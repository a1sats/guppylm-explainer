A from-scratch language model, explained

How a 9-million-parameter model learns to be a fish

GuppyLM is a tiny language model that talks like a small, friendly, slightly confused guppy. This guide starts with the whole pipeline in one picture, then goes deep into each stage. No prior machine-learning experience assumed — just comfort with code, arrays, and loops.

00 · Orientation

The whole thing in one picture

Training a language model is a loop with five stages. In GuppyLM, each stage is a small Python file you can read in one sitting.

The one sentence to remember

Training is repeatedly showing the model a sequence of tokens, asking it to guess the next token, measuring how wrong it was, and nudging every weight in the direction that makes the correct guess a little more likely.

Background: what “model” and “training” mean here

A model is just a function with a very large number of adjustable numbers inside it, called weights or parameters. You give it integers (token IDs) and it gives you scores for what should come next. At the start those numbers are random, so the scores are nonsense. Training is the process of choosing better numbers by looking at examples.

There is no database of facts inside the model and no rules written by hand. The only thing that changes during training is the value of those 8,726,016 numbers. Everything the fish “knows” is a pattern encoded in them.

Engineer’s translation

Think of a model as a function f(ids) → scores with 8.7M tunable constants. Training is fitting those constants to data by gradient descent. Inference is calling the function.

01 · Data

Where the training data comes from

Short answer: it is generated by a Python script in the repository. There is no web scrape, no book corpus, no chat logs, and no human labelers.

The file guppylm/generate_data.py contains hand-written vocabulary pools and templates. A pool is just a list of strings. A template is a function that picks one string from a few pools and glues them together. Run the function 60,000 times and you have a dataset.

Background: supervised learning in one paragraph

Most language-model training is supervised: you have examples of an input and the output you want. For a chat model the example is a user message and the assistant reply. The learning algorithm is never told “be friendly” or “answer in lowercase”; it only sees thousands of concrete (input, reply) pairs and is asked to make each reply more likely given its input. Style and personality emerge from the examples.

The pools behind the sentences

The generator defines the fish’s entire world in a handful of lists: 28 tank objects, 20 locations, 17 foods, 25 activities, 16 water descriptions, 10 light states, body parts, sounds, and 31 human concepts used to make Guppy confused. The narrowness is deliberate — it keeps the character consistent.

57,000 / 3,000train / held-out split (95/5)
11,611unique Guppy replies (19.4%)

That last pair of numbers matters. About four out of five replies are duplicates or near-duplicates of another reply. The model is not learning 60,000 independent facts; it is learning a compact, repetitive distribution over a small vocabulary of sentence shapes.

Why synthetic data?

The author’s stated reason is personality consistency: a real corpus would teach the model to sound like Wikipedia, Reddit, or code, and the fish voice would be diluted. Synthetic data also means no licensing questions, no cleaning pipeline, and a dataset small enough to generate in seconds. The cost is a model that is fluent only inside its tiny world.

Engineer’s translation

A dataset is a list of examples. Here each example is {input, output, category}. The generator is deterministic given a seed, so anyone can reproduce the exact dataset with python -m guppylm.generate_data.

02 · Tokenization

Text becomes integers

Neural networks do arithmetic. Before anything else, text has to become a sequence of integers. That conversion is the tokenizer, and it is trained on the same data as the model.

Background: why not feed in characters?

You could. Characters would make sequences very long (one ID per letter) and the model would spend most of its capacity learning to spell. You could also feed in whole words, but then any typo or new word becomes an “unknown” token. Byte-pair encoding (BPE) is the middle ground: common words become one token, rare words are split into meaningful pieces, and because it starts from raw bytes, any string is representable.

How BPE is learned

Start with every byte as its own symbol. Count adjacent pairs across the corpus. Merge the most frequent pair into a new symbol. Repeat. Each merge is recorded in order. To tokenize new text, apply the same merges in the same order. GuppyLM’s tokenizer learned 2,352 merges.

The vocabulary was requested as 4,096 entries, but the corpus only supported 2,418 real tokens before the frequency threshold stopped it. The model still allocates 4,096 embedding rows; the unused rows are simply never predicted. This is a normal BPE detail, not a bug.

Why tokenization changes the answer

Here is a real example from the published checkpoint. The model was asked to continue i feel. Then it was asked to continue i feel — with one trailing space. The space becomes its own token, and the context becomes one the model almost never saw during training.

i feel

i feel (trailing space)

Without the space, the model predicts “a”, “curious”, “not”, “happy”, “ok”, “peaceful” — all plausible continuations. With the space, it is nearly certain the next token is a period, because the rare trailing-space token pushes the context off-distribution. Tokenization is not a preprocessing detail you can ignore.

Engineer’s translation

The tokenizer is a lossless compression scheme learned from your corpus. The model never sees characters or words — only integer IDs. Two strings that look identical to you can be different token sequences to the model.

03 · The model

What the 8.7 million numbers actually do

GuppyLM is a “vanilla” transformer: six identical blocks, each with attention and a small feed-forward network. No exotic variants. That makes it a good specimen for learning the machinery.

Background: vectors, matrices, and tensors

A vector is a list of numbers. A matrix is a 2D grid of numbers. A tensor is the general term for an n-dimensional grid. A matrix multiply is the core operation: it takes a vector and produces a new vector by combining its entries with learned weights. If you have written y = W @ x + b in code, you already know the main primitive of a neural network.

The forward pass, stage by stage

Click a stage to see the exact tensor shapes for GuppyLM. Shapes are written as [batch, sequence, features]; for one prompt the batch is 1.

Embeddings: turning an ID into a vector

The token embedding is a lookup table with one row per vocabulary slot: 4096 × 384. Token ID 779 selects row 779, a vector of 384 numbers. A second table, 128 × 384, encodes position, because attention by itself has no sense of order. The two vectors are added.

Those 384 numbers per token are not human-interpretable features. They are learned coordinates. Training arranges them so that tokens used in similar ways end up in similar regions, because that makes prediction easier.

Attention: each token chooses what to read

For every token, the block computes three vectors: a query (what am I looking for?), a key (what do I offer?), and a value (what information do I carry?). The score between a query and a key is their dot product. Scores are divided by √64 to keep them from getting too large, masked so a token cannot see the future, and passed through softmax, which turns them into weights that sum to 1. The output is the weighted sum of the value vectors.

With 6 heads, the block does this six times in parallel with 64-dimensional subspaces, then concatenates the results. Different heads can specialize: one might track the previous word, another the topic, another punctuation.

Feed-forward, residual, and normalization

After attention, each token passes through a small two-layer network on its own: 384 → 768 → 384 with a ReLU. This is where most of the per-token computation happens. Both attention and the feed-forward are wrapped in residual connections (x = x + f(x)), which give gradients a short path back through the network, and preceded by LayerNorm, which rescales each token’s vector to a stable range.

Dropout randomly zeroes 10% of activations during training. It is a regularizer: it prevents the model from relying too heavily on any single pathway. It is switched off at inference.

The output layer

After six blocks and a final LayerNorm, a linear layer maps each 384-dimensional vector to 4,096 scores, one per vocabulary slot. These raw scores are logits. Softmax turns them into probabilities. The final linear layer shares its weight matrix with the token embedding table (“weight tying”), which saves 1.57M parameters and is a common trick.

Engineer’s translation

Attention is a learned routing table: each token computes a weighted average of earlier tokens. The feed-forward network is a per-token calculator. A block is x = x + attention(norm(x)); x = x + ffn(norm(x)). Repeat six times, project to vocabulary size, softmax.

04 · Learning

How the numbers get better

The model’s only job during training is to predict the next token. Everything else — grammar, tone, the fish personality — is a side effect of getting good at that one task.

Background: next-token prediction

Take a training string. At every position, the model sees the tokens before that position and outputs a probability for every token in the vocabulary. The correct next token is known because it is literally the next token in the string. The model is rewarded for putting high probability on it.

GuppyLM trains on the whole ChatML string, including the user turn and the special tokens. It is not told to ignore the user’s words; it learns to predict those too. That is simpler than masking the prompt, and it works fine at this scale.

The loss: turning “how wrong” into one number

Cross-entropy loss for one position is -ln(p), where p is the probability the model assigned to the correct token. If the model is confident and right, the loss is near zero. If it gives the correct token 1% probability, the loss is about 4.6. The training loss is the average over all non-padding positions.

Background: gradient descent

To reduce the loss, you need to know how each of the 8.7M weights affects it. That is the gradient: a vector of partial derivatives. Backpropagation computes it efficiently by applying the chain rule backwards through the network, reusing intermediate results from the forward pass.

The gradient points in the direction of steepest increase, so you step in the opposite direction. The learning rate controls step size. Too small and training crawls; too large and it overshoots and diverges. Play with it below — this is a one-dimensional analogy, while the real model has 8.7M dimensions.

The optimizer and schedule

GuppyLM uses AdamW, which keeps a running average of past gradients and their squares so each weight gets its own adaptive step size. It also applies weight decay (0.1), a small pull toward zero that discourages huge weights.

The learning rate is not constant. It warms up linearly for 200 steps, then follows a cosine curve down to 3e-5. Warmup avoids large early updates when the model is random; the cosine decay lets the model settle. Gradients are clipped to a total norm of 1.0 so a single bad batch cannot blow up the weights.

Learning-rate schedule

3e-4 → 3e-5 · 200-step warmup, then cosine

The real numbers

After training, the published checkpoint scores 0.407 cross-entropy on the 3,000 held-out conversations. That is a perplexity of 1.50 — on average, the model behaves as if it were choosing among about 1.5 equally likely next tokens. This is impressively low, but only because the task is narrow and repetitive.

Engineer’s translation

Training solves an optimization problem: minimize the average -log p(correct next token) over 57,000 examples. Backprop gives the gradient; AdamW takes the step; the schedule controls how big the steps are over time.

05 · The training loop

One training step, line by line

What one step means in numbers

32sequences per batch
128max tokens per sequence
10,000optimizer steps

One step sees 32 conversations, each truncated to at most 128 tokens. Over 10,000 steps the model sees 320,000 sequences, which is about 5.6 passes over the 57,000-example training set. This is why “steps” and “epochs” are different: an epoch is one full pass; a step is one batch and one weight update.

The shape is the important part: a rapid drop from random guessing (loss near 8.5, close to ln 4096 ≈ 8.32) toward the low-loss regime, then a slow grind. The published 10,000-step run continues this grind down to 0.407.

What gets saved

Every 200 steps the loop evaluates on the held-out set and saves best_model.pt if the held-out loss improved. It also saves periodic checkpoints and a final model. A checkpoint contains the state dictionary (all 8.7M weights), the model config, the step number, and the evaluation loss. Loading is just constructing the same architecture and copying the numbers in.

Engineer’s translation

A step is: get a batch → forward pass → loss → backward() → clip gradients → optimizer step → zero gradients. Ten thousand of those, with a schedule on the step size, and you have a fish.

06 · Inference

From weights to a reply

Generation is a while loop around the forward pass. The model produces one token, appends it to the input, and runs again. The only state is the growing sequence.

The prompt format

GuppyLM is trained on ChatML, a simple text convention that marks who is speaking. The inference code builds the prompt by concatenating the roles, then leaves the assistant header open for the model to continue.

<|im_start|>user
hi guppy<|im_end|>
<|im_start|>assistant
hello. the water is nice today.<|im_end|>

Because every training example has this shape, the model learns that after an assistant header it should produce fish text, and that <|im_end|> means “stop”. There is no separate system prompt and no instruction-tuning stage; the personality is entirely in the weights.

The sampling loop

  1. Tokenize the prompt into IDs.
  2. Run the forward pass. Take the logits at the last position.
  3. Divide by temperature; optionally keep only the top-k logits.
  4. Softmax to probabilities; sample one token.
  5. Append it. If it is <|im_end|>, stop; otherwise repeat.
  6. Decode the generated IDs back to text and truncate at the end marker.

The default inference settings are temperature 0.7, top-k 50, and at most 64 new tokens. Lower temperature makes the fish more predictable; higher temperature makes it more likely to wander into nonsense.

Why multi-turn chat degrades

The context window is 128 tokens. Every prior turn consumes some of it. By turn three or four, the earliest instructions and the original topic have fallen out of the window, and the model is conditioning on a truncated conversation. The repository’s own documentation recommends single-prompt use for this reason.

Shipping it: quantization and ONNX

The FP32 weights are about 34.9 MB. The exported ONNX model stores them as 8-bit integers (uint8 quantization), which brings the download to about 10.5 MB. The browser demo runs that model locally through WebAssembly — no server, no API key. Quantization is lossy in principle, but at this scale and for this narrow distribution the quality loss is small.

Engineer’s translation

Inference is while not done: logits = model(ids); next = sample(softmax(logits / T)); ids.append(next). No gradients, no weight updates. The model is a pure function of the token sequence.

07 · Results and limits

What this model learned, and what it did not

GuppyLM is a successful demonstration of the full pipeline. It is not a general assistant, and the difference is instructive.

What the numbers say

0.407held-out cross-entropy
1.50perplexity (e^0.407)
8.7Mparameters
128tokens of context

A perplexity of 1.50 means the model is rarely surprised by the next token in the held-out set. That sounds impressive until you remember what the held-out set is: more samples from the same template generator. The model has learned the generator’s distribution extremely well. It has not learned English, reasoning, or facts about the world.

Why the low loss is not general intelligence

Nineteen percent of the replies are unique, so the model can legitimately memorize and interpolate among a few thousand sentence shapes. When you ask something outside the 60 topics, there is no learned behavior to fall back on; the model will still produce fish-flavored text, but it will not answer the question. That is the expected outcome of training on a narrow synthetic distribution.

Scale, for calibration

Parameter counts are not a perfect measure of capability, but they are a useful order-of-magnitude check. GuppyLM is about 14× smaller than GPT-2 small and roughly 20,000× smaller than GPT-3.

GuppyLM8.7M
GPT-2 small124M
GPT-3175B

Bars are log-scaled. Public approximate parameter counts.

What would make it a general model

Three things, roughly in order of importance: far more diverse data (the current corpus is one character in one tank), much more capacity and compute, and a longer context window. Instruction tuning and preference optimization would come after that. GuppyLM deliberately omits all of it so the mechanics stay legible.

The honest summary

GuppyLM is a complete, reproducible LLM pipeline in miniature. It demonstrates data generation, tokenizer training, a transformer forward pass, backpropagation, optimization, evaluation, quantization, and deployment. Its low loss measures fidelity to a narrow synthetic distribution, not intelligence.

Eight questions

If you remember ten things

  1. The data is synthetic: Python templates, not web text.
  2. A tokenizer turns text into integer IDs; it is learned from the same corpus.
  3. GuppyLM has 8,726,016 weights, and those weights are the entire model.
  4. A transformer block is attention plus a feed-forward network, with residuals and LayerNorm.
  5. Attention lets each token take a weighted average of earlier tokens.
  6. Training objective: make the correct next token more probable, measured by -ln(p).
  7. Backpropagation computes the gradient; the optimizer takes the step.
  8. Batch size, learning rate, warmup, and weight decay are the main knobs.
  9. Generation samples one token at a time from softmax(logits / temperature).
  10. Low loss on a narrow distribution is easy; generalization is the hard part.
